# Brief 130: Likha encodes and checks the chatbot's orders itself, first in shadow beside the Google Sheets

## Why
Today every order the Likha chatbot takes is appended by the flow's sheet step (`FlowEngine::sheet`, `Outbox::appendRow`) to the order spreadsheet tab "All Orders". Two Apps Scripts then do the encoding and checking in Google Sheets:
1. **AUTO ENCODE** (`auto-encode.gs`, bound to the macro sheet): one row at a time copies the order into ENCODER row 2, parses the EXTRACTED DETAILS block (name, 09-phone, province, city, barangay), asks GPT for Address Line 1 and for any missing field, parses item/qty/price from SHOP DETAILS, matches province/city/barangay against LocationData with the sheet formulas in `encoder-formulas.md` (`Macro()`: build P1 word by word, keep a word only if Q1's first candidate contains it, score 1/2/4, remark + ✅/❌), then writes the encoded row (A..N) into the AFTER MACRO spreadsheet's DATABASE tab **at the same row number** as the All Orders row.
2. **1.0 OUTPUT** (`output-1.0-LIKHA11_1.gs`, bound to AFTER MACRO; three copies run in parallel on different rows, identical code): per DATABASE row, phone check, Page/Price/Qty checker → R, fuzzy address checker (Levenshtein ≥ 0.7, uses column M) → S, suggestion lists T/U/V from LocationData, GPT pick-from-list fixes for province/city/barangay (uses column K), GPT verify → W, GPT fill of Full Name / Address Line 1 when blank; logs in GPT_DEBUG / GPT_VERIFY / GPT_NAMEADDR.
Then the sheet "DATABASE - MIRRORED" (O = W if W else S; P = PROCEED when O = ✅) is pulled into `macro_output` by the Macro import, and the raw row by the Likha import.

The owner wants orders that Likha's own chatbot creates to stop going through Google Sheets. This is **its own new process**, separate from Astra / Checker 1 / the night run / MacroChecker: do not call, change or reuse their code, settings, schedules or the J&T list file. Step one (this spec) is an exact copy of the two scripts running **in shadow**, with a compare page, plus a per-page switch to go live later.

Time limits, sleeps, locks and the 3 parallel copies are sheet mechanics: drop them. | The compare must show whether Likha matches the sheet; fixes come after, as the owner's call. |
| **Input** = the row the flow's sheet step writes, for pages whose encode mode is `shadow` or `live`: the same values in the All Orders column order (A date, B page, C name, D phone, E all user input, F shop details, G extracted details, H price, I status — map by the tab's header names if the step's columns differ; document how). Keep the spreadsheet id, tab and the **row number** from the append result (`content.row` / `range`, e.g. `'All Orders'!A23823:I23823`). Fields the scripts read from other cells follow the scripts (ENCODER B..I = All Orders B..I as copied by `transferOneRowColumnsBtoIWithRowTag`; DATABASE K/L/M as written by `storeAndTransferEncoderValues`). | Same input as the sheet gets. |

If the two lists are identical, say so in the result. Tests use small fixture lists. | Exact copy; precedent: Likha keeps the J&T list as a file, not a table. |
| **Config, no new settings table.** Per page in `page_settings` (provider `order_encode`): key `mode` = `off` (default) / `shadow` / `live`; key `compare_sheet` = the AFTER MACRO spreadsheet link or id; key `macro_sheet` = the macro spreadsheet link or id (for LocationData). Allow exactly these keys for that provider in the narrowest way, and hide provider `order_encode` from the generic Page settings grid only if it would clutter it (say which). Never log or show the key. | Owner's Page \| Key \| Value rule; cheaper model swappable without code. |
| **Storage: one new table** `order_encodes` (one row per order): page, psid, flow run/chat ids if available, source spreadsheet id + tab + row number (unique together), mode at the time, input (JSON of the A–I values), outputs (name, phone, address line, province, city, barangay, item, COD, encode remark, encode status icon, R, S, T/U/V counts or text, W, final O, PROCEED yes/no), `steps` JSON (each step and each GPT call: step name, model, prompt hash, status like the scripts' WROTE_*/SKIP_*/ERR_*, raw response truncated to 2,000 chars, tokens, ms), `sheet` JSON (the DATABASE row values read back for compare), compare result JSON (per field: same / different / sheet blank / likha blank), `macro_output_id` (filled in live mode), timestamps, error. One migration, additive only. | Per-order results with a step log do not fit Page \| Key \| Value, and shadow results must never touch `macro_output` (reports would double). The owner approves the migration at release. |
| **Shadow run.** When the sheet step of a `shadow` page writes a row, dispatch one queued job `EncodeOrder` (database connection, new queue `encode`, timeout 600, tries 2 with backoff 60; a GPT HTTP error is recorded like the script records it, not retried forever). The flow never waits for it and never fails because of it. It writes only `order_encodes`. | Same timing as the sheet, zero risk to the bot. |
| **Compare.** Command `order-encode:compare` (every 10 min) takes shadow rows not yet compared, older than 15 min and younger than 48 h, reads the DATABASE row with the **same row number** from the page's `compare_sheet` (batch reads, A:W) plus "DATABASE - MIRRORED" O/P for that row, and checks it is the same order (DATABASE A timestamp text and J page equal ours; otherwise mark "row mismatch"). Compare field by field after trim (case-insensitive for names/places; phone as digits): name, phone, address line, province, city, barangay, item, COD, R, S, W, final O, PROCEED. | Row number is the exact key (the bot's append row = the DATABASE row). |

Read-only. English UI. | The owner and the analyst judge readiness from it. |
| **Live mode (built, not switched on).** For a `live` page the flow's sheet step does **not** append to Google Sheets (it records a sheet reply with status `skipped` and note "encoded in Likha", and continues on the success port); instead `EncodeOrder` runs and then creates the `macro_output` row the two imports would have produced: Likha-import fields (TIMESTAMP text "HH:mm dd-MM-yyyy", PAGE, FULL NAME/fb_name, PHONE NUMBER, all_user_input, shop_details, extracted_details, ITEM_NAME, COD, botcake_psid) plus the Macro-import fields from our result (FULL NAME/PHONE/ADDRESS/PROVINCE/CITY/BARANGAY per the Macro import's protected-field rules, CXD, AI ANALYZE, APP SCRIPT CHECKER = final O, STATUS = PROCEED when O = ✅ else blank), using `OrderIdentity` so a duplicate is never inserted. No page is set to live in this spec; switching is a page setting the owner flips later. | One more spec avoided; off by default. |
| No change to Astra, MacroChecker, Checker 1, the night run, the Likha/Macro imports, the J&T file, or any live flow. | Separate process (owner, 2026-10-23: "iba to, ibang process dapat to"). |

## Threat model and risk
Untrusted: customer chat text (goes into GPT prompts and onto the compare page — escape it), GPT output (validate against the lists exactly as the scripts do), sheet values. Trusted: the owner's settings. Risk tier: medium (writes orders only in live mode, which stays off). Secrets: the OpenAI key only from config/env; never in logs, `steps`, the page or tests.
