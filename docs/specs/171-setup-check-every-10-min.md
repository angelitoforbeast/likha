# Brief 171: the chatblast setup check every 10 minutes, with a red banner

## Why
The chatblast setup check (app/Services/ChatblastSetupCheck.php via BotcakePageSetup, command `botcake:setup-check --all`, scheduled in routes/console.php daily 21:30 Manila) confirms per page that exactly one Botcake flow and one custom field carry the Setup box names, and that the template is APPROVED with {{1}}. A page with an X is not Ready. Today it runs once a night, and an X shows only on /chatblast/page-settings (red row, Check column). Marketing changes or duplicates flows during the day, so a broken page can go unnoticed for most of a day. The owner wants it checked every 10 minutes and a problem easy to notice.

## Decisions (do not reopen)
| # | Decision | Why |
|---|---|---|
| 1 | Run the setup check **every 10 minutes from 06:00 to 23:00 Manila, skipping 08:45–10:30** (the morning chatblast burst fills each page's Botcake lane; the check shares that 2-requests-per-second lane, `shared(sha1($token))`). Keep the existing 21:30 run for all pages. Put the window in config (config/services.php or the existing chatblast/botcake config) with these defaults; no env var required. `withoutOverlapping` and `runInBackground` so a slow run never stacks or delays other schedules. | Owner: "10 minutes". Catch flow changes before the next send without slowing the burst. |
| 2 | The 10-minute run checks **only pages that chatblast actually sends for** (find how the sender picks pages — ChatblastSender / Chatblast::missingByPage / ChatblastReady / page settings — and use the same rule; state the rule in the result). Same checks and the same outcome rules as today (exactly one flow and field = OK and the check writes the ID as system; none or 2+ = X; template rule unchanged; Botcake unreachable = grey "Check failed", previous result kept). The hourly delivered check (`botcake:setup-delivered`) stays as is. | Spend Botcake calls only where they matter; no change to how the check decides. |
| 3 | **No write when nothing changed**: a 10-minute run that finds the same IDs and the same result must not add page-setting rows, history entries or "changed" timestamps that would make a page lose Ready or need a new test. Only a real change (new ID, new X, X cleared) is written. Verify the current code; fix if it writes every run. | 100+ runs a day must not flood History or flip Ready. |
| 4 | **Red banner** on every Chatbot and Chatblast screen (the same layout and place as the spec 169 banner in resources/views/layouts/chatblast.blade.php, `$cbProblems`) while any page's latest setup check has an X or "Sent N, none delivered": "⚠ <page>: <reason> — open Page settings" linking to /chatblast/page-settings (filtered or anchored to that page if the screen supports it). At most 3 pages, then "+N more". Reasons as the Check column shows them (e.g. "2 flows named UPDATE SHIPPING STATUS 2026", "No custom field named message in Botcake", "token invalid", template reason). A grey "Check failed" (Botcake did not answer) is not shown. Cached ≤ 60 s. Visible to the roles that see the Chatbot/Chatblast menu (same as 169). If both banners apply, show both (169 first), each compact; must fit at 390 px. It disappears by itself after the next passing check. | Owner: easy to notice without opening page-settings. |
| 5 | No GC/Messenger message, no auto-pause, no change to sending, flows, sequences, the Ready rules, or the names in the Setup box. No new tables. | Owner: "huwag na muna yung GC message"; small and safe. |

## Cases (S-171)
P1: .1 the schedule has the 10-minute setup check limited to 06:00–23:00 Manila and not 08:45–10:30, plus the 21:30 all-pages run (test the schedule entries and the window with a frozen clock at 08:50, 10:40, 23:30); .2 the 10-minute run checks only the chatblast pages (a page outside the rule gets no Botcake call, Http faked); .3 same IDs and same result twice → no new page-setting rows or history, Ready unchanged; a new duplicate flow → X written once, page not Ready; X cleared → OK written, Ready per existing rules; .4 banner: a page with "2 flows named …" → banner on a Chatbot screen and a Chatblast screen with the page, reason and link; 4 pages with X → 3 listed + "+1 more"; "Check failed" only → no banner; no problems → no banner; .5 non-chatbot roles see no banner; .6 both 169 and 171 banners show together when both apply; .7 existing setup-check, page-settings and 169 tests pass. P2: .8 390 px.
