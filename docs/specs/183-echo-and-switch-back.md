# Brief 183: use echo to know who answered; fix the switch back; read Forbeast's honest lag

## Why
Every Meta app subscribed to a page gets an **echo** for every message the page sends, carrying the sending app (app_id) — Forbeast, Botcake, Page Inbox/Business Suite (a person), others. Today Likha only counts echoes. With them Likha can tell, per customer, who answered and when, catch a customer message nobody answered, and catch double replies from two bots. Forbeast will forward echo (and send_status) in batches (Forbeast spec 027); until then echoes arrive one by one. On 2026-10-28 the watcher moved 30 pages to Botcake; none came back by itself: pages moved with condition `health` ("Forbeast did not answer") have no switch back, and pages already switched back at 17:42 were limited to one switch back per 6 hours.

## Decisions (do not reopen)
| # | Decision | Why |
|---|---|---|
| 1 | **Store echoes minimally.** For each echo (Forbeast gateway events; and Botcake's if its payload carries them — check): page, customer psid, Meta message id, time, sender app id → sender label (Forbeast / Botcake / Page Inbox-person / other, map known ids: Forbeast 1115162827653315, Botcake 556376998159104, Chatbot Builder 573598697063667, Page Inbox 263902037430900), and a short text hash plus the first 200 chars. Follow the lean-schema precedent (existing chat/event tables first: botcake_chats with a source, chatbot_events, …); a new table only if rows truly cannot hold it — justify. Accept batched echoes (an array body from Forbeast) and single ones; idempotent by Meta message id. | Echo becomes useful data. |
| 2 | **Who answered** (per customer, latest): show on the Inbox chat (a small label on each page message: Bot (Forbeast) / Botcake / Person / other app) and expose for other features. **Do NOT pause or step back the bot when a person replies** (owner does not want that). | Visibility only. |
| 3 | **Unanswered alarm:** a customer message on a bot-On page with **no echo from any sender within 5 minutes** (config) → count it as "unanswered" in Bot Health (per page, last 60 min) and include pages with ≥ 3 unanswered in the existing red banner logic (spec 169) as reason "N customers not answered in 5 min". Exclude attachments the bot ignores by design, pages with the bot Off, and test runs. | Catches what the "Forbeast copy" check misses. |
| 4 | **Double replies:** two different sender apps replying to the same customer within 60 s → count per page in Bot Health ("double replies"), with the latest examples. No automatic action. | Coordination between bots. |
| 5 | **Switch back fixes:** pages the watcher moved with condition `health` also switch back after 30 healthy minutes (same rules as 175); the per-page limit becomes **one switch back per 60 minutes** (config, was 6 h). A person's manual change still always wins. | Pages stayed on Botcake. |
| 6 | **Honest lag:** when Forbeast's per-page health has `inbound_lag_seconds`, use it as today (it will count in-flight work after Forbeast 027); additionally, treat "customer messages on gateway pages with no Forbeast copy AND no echo from any sender after 300 s" as evidence for a switch (the echo check replaces part of the Botcake-copy comparison; keep the existing settle window after a move). | Better evidence. |
| 7 | No change to sending, flows, chatblast, Forbeast. | Safe. |

## Cases (S-183)
P1: .1 an echo from Botcake's app id for page P/customer C is stored with sender "Botcake" and shows on the Inbox chat; a batched array of 3 echoes is stored once each (idempotent); .2 a person reply (Page Inbox app id) is labelled "Person" and the bot is NOT paused; .3 a customer message with no echo in 5 min on a bot-On page → unanswered count and banner when ≥ 3; an ignored attachment or bot-Off page is not counted; .4 Forbeast and Botcake replies within 60 s to the same customer → a double reply counted; .5 a page moved with condition health switches back after 30 healthy minutes; a second switch back within 60 min is refused; after 60 min allowed; a manual change after the switch blocks it; .6 the switch evidence uses "no copy and no echo after 300 s"; .7 existing ForbeastWatch/BotHealth/Chatblast/Botcake suites pass.
