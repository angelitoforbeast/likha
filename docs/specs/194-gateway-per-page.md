# Brief 194: two gateways — each page replies through Forbeast or incepxionbot, and switches between them on its own

## Why
Today Likha knows one gateway (one GATEWAY_URL: Forbeast). The owner is building a second gateway, incepxionbot.com: the same Forbeast software running with a second Meta app (Incepxion V2, already approved by Meta), so that if one gateway stalls the pages keep replying through the other. Botcake stays as the last fallback. A page will be connected in both Meta apps, so both gateways receive the same customer message; only one may reply.

## Decisions (do not reopen)
| # | Decision | Why |
|---|---|---|
| 1 | **Gateways are configured, not hard-coded:** the existing Forbeast settings stay as gateway `forbeast` (unchanged env names, so nothing changes on deploy), plus an optional second gateway `incepxionbot` with its own env set (URL, key, webhook secret, site key/secret — mirror exactly what `forbeast` has, e.g. `GATEWAY2_*` or `INCEPXIONBOT_*`; pick one naming and document it). A gateway with no URL is "not set up". No new table. | Secrets stay in env; old config keeps working. |
| 2 | **Per page:** a page row (Page \| Key \| Value) `gateway` = `forbeast` or `incepxionbot` says which gateway is active when the page's provider is the gateway; missing = `forbeast`. Per-gateway page tokens/webhook secrets are stored like today's Forbeast token rows, one set per gateway. The Pages screen shows and lets staff set the gateway (only gateways that are set up and have a working token for that page), the same way provider is set today. | Database-driven, like the rest. |
| 3 | **Inbound from both, processed once:** `/gateway/events` accepts events from either gateway (verify with that gateway's secrets; record which gateway delivered). The same Meta message arrives twice (once per app): dedupe by Meta's message id (mid) — and for events without a mid by the gateway-independent key the code already uses — so the first arrival is processed and the second is dropped silently. Comments and page-values calls the same. | No double processing. |
| 4 | **Outbound only via the active gateway:** sends, typing/seen, comment replies and site calls go through the page's active gateway with that gateway's token. Never both. | No double replies. |
| 5 | **Automatic switch:** the watcher (today Forbeast → Botcake) checks each gateway's health on its own. When the page's active gateway stalls (same rules as today's Forbeast stall), switch the page to the other gateway if it is set up, healthy and has a working token for the page; only if neither works, fall back to Botcake as today. Switch back to the page's chosen gateway after 30 healthy minutes (same as today). Every switch is written to the page history with the reason, like today's switches. A "manual" choice is never switched back automatically. | The owner's redundancy, using the rules that already work. |
| 6 | Speed, Bot Health and the live page show the gateway name where they show "Forbeast" today (or "via" counts per gateway); `chatbot_replies.via` records the gateway that sent. No redesign. | They can tell which gateway served. |
| 7 | Applies to Incepxion: Incepxion today has no gateway; with this change it can use incepxionbot alone (then it is its only gateway). | Same code. |
| 8 | No change to flows, AI, orders, sequences logic, broadcast splitting, or existing data. | Safe. |

## Cases (S-194)
P1: .1 no second gateway configured → everything behaves exactly as before (existing suites unchanged); .2 page set to incepxionbot → sends, typing and comment replies go only to incepxionbot with its token; .3 the same customer message from both gateways → processed once, one reply; .4 the active gateway stalls → the page moves to the other healthy gateway, history row written; after 30 healthy minutes it moves back; .5 both gateways stalled → Botcake, as today; .6 an event signed with the wrong gateway's secret → 401; .7 a page without a token on the other gateway is not moved there; .8 Pages screen shows and sets the gateway; .9 Incepxion with only incepxionbot set up works as its gateway.
