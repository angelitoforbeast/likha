# Brief 121: orders without a Facebook name still import, dedupe and link to the right customer

Orders come from the chatbot sheet step into Google Sheets: tab "All Orders" (A date, B page, C NAME = Facebook name, D PHONE NUMBER from the AI step `GPT PHONE NUMBER`, E ALL USER INPUT = everything the customer typed, F SHOP DETAILS, G EXTRACTED DETAILS = AI-extracted name/phone/address, H PRICE, I STATUS). The **Likha import** (`ImportLikhaFromGoogleSheet`) reads tab "TO WEBSITE" A2:I (formula copy of All Orders) and creates/updates `macro_output`. The **Macro import** (`ImportMacroFromGoogleSheet`, "AFTER MACRO …" sheets, "DATABASE - MIRRORED" A2:Q) updates the same orders with encoded addresses. Both find an existing order by **TIMESTAMP (minute) + PAGE + fb_name**. Customer PSIDs are set by `BotcakeCustomerMatcher` (fb_name, then phone, against Botcake customers in `botcake_psids`) and `BotcakePsidMatcher`.

Pages that reply through Forbeast without Botcake give no Facebook name (blank C), and the AI step that fills D sometimes fails. Then: two nameless orders on the same page in the same minute are treated as one (the second overwrites the first), and the order cannot be linked to its customer.

## Decisions
| Decision | Why |
|---|---|
| **Phone for an order** = D normalized to `09XXXXXXXXX`; if D is blank/invalid, extract from E, then G: PH mobiles in the forms 09XXXXXXXXX, 9XXXXXXXXX, +639…, 639…, allowing spaces/dashes; use it only if exactly ONE distinct number is found, else none. One helper used by both imports and the matcher. Never invent; never use prices or short numbers. | Reliable key without AI. |
| **Likha import key**: if fb_name is present, unchanged. If fb_name is blank: TIMESTAMP + PAGE + phone. If no name and no phone: always insert a new row (never merge) and mark it in an existing free-text/flag column of `macro_output` that staff see (pick the least surprising existing one, e.g. the checker/notes column; document which) with "No name / no phone". | No overwritten orders. |
| **Macro import key**: same rule for its update/insert match (fb_name blank → TIMESTAMP + PAGE + phone; if still no phone → only an exact TIMESTAMP + PAGE + identical all_user_input match; otherwise do not touch any existing row and log it on the run item). | Macro never hits the wrong order. |
| **PSID link fallback** (in `BotcakeCustomerMatcher` or a small new step it calls) for orders with no PSID and blank fb_name: by phone, in this order — (1) chatbot customer values of that page (`chatbot_customer_values` key `gpt phone number`, normalized) → PSID if exactly one; (2) the page's customer chats (`botcake_chats`, `active()` only) whose message contains that phone (digits) → PSID if exactly one; else leave empty (ambiguous = no write, as today). Write `botcake_psid` (and `botcake_ad_id` once, as the matcher already does). | Link without a name, never to the wrong person. |
| **Flow condition rule "has phone number"**: a new condition rule (e.g. `has_phone`) in the flow engine/editor that is true when the chosen variable contains one valid PH mobile by the helper above (not a 3-digit fragment). English label "has a phone number". Do NOT edit any live flow; the owner will switch n20 and add a check before the sheet step later. | Replaces keyword lists like "901…999" that match prices. |
| No migration. | Lean. |
