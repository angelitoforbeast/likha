# Brief 132: an "Encode order" step in the bot flow

## Why
Spec 130 put the sheet scripts' encode + check into Likha (`App\Services\OrderEncode\*`, job `EncodeOrder`, table `order_encodes`, compare page `/order-encode`). Its "live" switch is a hidden page setting (`page_settings` provider `order_encode`, key `mode`) that silently intercepts the flow's Sheet step. The owner wants the process **in the bot flow itself** ("gusto ko mailagay sa botflow yung process"): a step you can see, place and edit in the flow builder, like the existing Send / AI / Sheet / Sequence steps. It will be switched on per flow after the shadow run passes; building it now changes no live flow.

## Decisions (do not reopen unless something is actually broken)
| Decision | Why |
|---|---|
| **New node type `encode_order`** in `FlowEngine::execute` and the flow builder (`resources/views/chatbot/editor.blade.php` and whatever the existing node types use: palette, config panel, validation in the flow graph/save code, labels, node summary). English UI: palette name **"Encode order"**, short help "Encodes and checks the order in Likha and saves it to the orders (macro output). Replaces the Google Sheet step." | Visible and editable in the builder, same as the other steps. |
| **Config (all shown and editable in the panel):** the order fields with the same variable pickers the Sheet step uses for its columns — Date, Page, Name (FB name), Phone, All user input, Shop details, Extracted details, Price (prefilled with the same variables the page's current All Orders Sheet step uses when the builder can find one, else empty); **Also write to Google Sheet** (off/on + spreadsheet link + tab, default off) for a transition period; **On failure**: "Write to Google Sheet instead" (default, needs a sheet link) or "Continue without saving" (shows a warning). Show the models in use (read-only, from `order_encode_model_extract` / `order_encode_model_checker`) with a link to where they are set. | The owner wants every input of a decision shown and editable. |
| **Run:** the node builds the same A–I row the Sheet step would write, creates an `order_encodes` row with mode `live` (spreadsheet = the fallback sheet or `flow-node`, tab, row_number null) and dispatches `EncodeOrder` — reusing spec 130's live path (`LiveOrder` creates the `macro_output` row with the import-equivalent fields and `OrderIdentity` dedupe; on failure `Runner::fail` writes the row to the fallback sheet when one is set). The flow continues on **next** at once (it never waits for GPT); port **failed** only when the order cannot even be queued. If "Also write to Google Sheet" is on, append the row like the Sheet step does (same Outbox call and reply log). Test tab: never encodes; shows "Test: would encode the order" and the row it would send. Record a `chatbot_events` row `encode_order` and a reply row of kind `sheet` or a new kind the inbox/Results already tolerate (pick the least surprising; document it) so Results/Inbox keep counting orders exactly as today — the existing `order` event must still be emitted the same way it is for a Sheet-step order. | One live path, no lost orders, reports unchanged. |
| **Page setting `order_encode.mode`:** keep `off` and `shadow` (the shadow hook on the Sheet step stays exactly as spec 130). Value `live` stays accepted for backward compatibility but the Page settings help text says "Use the Encode order step in the flow instead"; the node works regardless of the page mode. No flow is edited by this spec. | One clear way to go live: the flow step. |
| **/order-encode** shows `live` orders too (filter "Mode: shadow / live"), and a live order links to its `macro_output` row. | The owner can watch live orders the same way. |
| No migration. | Everything fits the existing tables. |

## Threat model and risk
Untrusted: customer text in the variables (escape in the builder and the compare page), GPT output (validated by spec 130's rules). Trusted: the flow editor (owner/staff). Risk tier: high once a flow uses it (it creates real orders) — this spec ships it unused; tests must prove no duplicate orders and no lost orders.

## Done when
- Tests: the builder lists "Encode order", saves and reloads its config, validates a missing fallback sheet when "Write to Google Sheet instead" is chosen; the engine queues one `EncodeOrder` with mode live and the right A–I row and continues on next; Test tab never encodes; "Also write to Google Sheet" appends once; a failed encode writes the row to the fallback sheet once and never creates a second `macro_output` row on retry; a rerun of the same run does not create a second order; the `order` event and Results counts are the same as for a Sheet-step order; `/order-encode` filters live; no existing flow changes (snapshot of a stored flow renders and runs as before).
- `php vendor\phpunit\phpunit\phpunit tests/Feature/OrderEncode tests/Feature/Chatblast tests/Feature/PageSettings tests/Feature/Botcake tests/Feature/NightRun` plus your new tests pass; note the known local-only failure (missing Google credentials file) separately.
- Result: files, the node's config keys, the reply/event kinds used, how Results/Inbox count it, screenshots or a short description of the builder panel, commits.

## Out of scope
Switching any flow to the node; removing the Sheet step; changing the encode rules; deploy.
