# Brief 172: per-ad setup on a chatbot page (ad groups, page values as the default)

## Why
Today every chatbot page has one setup on /chatbot/pages (Page settings): the flow (`chatbot.flow_id`, ChatbotPage::flow), and the page values / botfields (ChatbotPage::botfields, PageSettings rows with history: Main Flow, Main Flow 2, item name, price, quantity, picture, seq_N / seq_img_N, …). Every customer gets the same flow and values whatever ad they clicked. Pages like "Precious Lopez" sell several items through different ads (60 ads in 7 days), so the bot cannot answer with the right item. The ad ID is already captured per customer (botcake_psids.ad_id / ad_ids from Botcake; the referral ad_id from the Forbeast gateway, HandleGatewayEvent; ChatbotTags::adId) and is present for ~97% of new Likha customers (~75% on Incepxion), but it is used only in reports. The owner wants the bot's setup to optionally depend on the ad, with many ads able to share one setup, and the page's current values as the default.

## Decisions (do not reopen)
| # | Decision | Why |
|---|---|---|
| 1 | **Where:** on /chatbot/pages (the Chatbot page settings), the pages list stays as it is. The ad option appears **only when a page is opened / configured** (its existing edit or expand view): a section "Ad groups" below the page's values. A page with no groups behaves exactly as today. | Owner: show the option only when configuring the page; optional. |
| 2 | **Ad groups ("merge"):** per page, zero or more groups. A group has a **name** (e.g. "Item A"), a **list of ad IDs** (digits only), and **optional values** for these keys only: **item name, price, quantity, picture, Main Flow, Main Flow 2, the flow (flow_id), and the sequence values (seq_N / seq_img_N)**. Find the real keys in ChatbotFields / PageValues / the order vars and list them in the result. Anything a group leaves empty uses the **page value** (the default). Forms (fill-up form, loop form), shop details, AI settings, provider/connection keys and on/off stay page-only. | Owner: many ad IDs can share one item; empty = page default. |
| 3 | **One ad ID belongs to at most one group per page**; saving a duplicate is refused with a clear message naming the other group. Ad IDs may be added by ticking from a list or by typing/pasting (comma, space or newline separated). Removing a group or an ad ID is allowed (with history). | No ambiguity about which setup applies. |
| 4 | **"Ads not in a group yet"** list inside the page's Ad groups section: the ad IDs seen for that page in the last 30 days (from botcake_psids / the chats the site already stores), with the ad name from ads_manager_reports when known (campaign / ad set / headline, as PsidCoverageController::adNames does), the number of customers and the last time; tick several → "Add to group" (existing or new). Bounded and paginated or capped (show the top 50 by customers, with a search box) so it stays fast. | Easy to assign; new ads are visible. |
| 5 | **Resolution:** when a run needs the flow or a value for a customer: take the customer's **latest** ad ID for that page (the newest known one; state in the result exactly which source and why); if that ad is in a group of this page, use the group's value for each key the group sets, else the page value; no ad ID, or an ad in no group → the page values exactly as today. A run that a sequence starts uses the group the customer had **when they entered the sequence** (record it on the subscription or the run state with what exists; no new table), so a sequence does not switch midway. Test runs on /chatbot (no customer) use the page values unless the test lets you pick a group (optional; nice to have, P2). | Owner's rules: ad decides, page is the fallback. |
| 6 | **Orders follow the group:** where the bot or the encode reads the page's item name / price / quantity / picture for an order (OrderVars, Encode order, J&T item name, PageExpectedItem, content checks), it uses the resolved value for that customer, so the order matches the item the customer was shown. List every place you changed and every place you deliberately left on page values. | The encode and J&T must match the reply. |
| 7 | **Storage: no new table.** Groups and their values are rows in the existing page settings (Page \| Provider \| Key \| Value, with active flag, history and Restore), e.g. a provider or key prefix per group — check the existing precedent in PageSettings / ChatbotFields first and follow it; state the scheme in the result. History and Restore work for group values like other values. Group rows never appear as page values in other readers (chatblast, Forbeast PageValues API, the setup check, exports) unless intended; the Forbeast values API keeps returning the page defaults only. | Lean schema; row-based like the rest. |
| 8 | **Who can edit:** the same users and roles who can edit the page's values on /chatbot/pages today (same check, server-side). Others see nothing of it. Same throttles as the page value writes. | Owner: marketing edits. |
| 9 | Caching: per-run reads stay cheap (one query or the existing BotConfigCache pattern; invalidate on write). No change to sending, rate lanes, messaging_type, the 24-hour rule, chatblast, comments, or Forbeast. Comments are out of scope. | Safe and fast. |

## Cases (S-172)
P1: .1 a page with no groups → runs, values and orders are exactly as before (existing tests pass unchanged); .2 page "P" with group "Item A" (ads 111, 222; item "Serum", price 499, Main Flow text X) — a customer whose latest ad is 222 gets Main Flow X and an order with item "Serum" 499, while Main Flow 2 (left empty in the group) is the page value; .3 a customer with ad 333 (in no group) or no ad → page values; .4 a customer who clicked 111 then 333 → page values (latest ad wins); 333 then 111 → Item A; .5 a group with its own flow_id → that flow runs for its ads; .6 a customer in a sequence keeps the group they entered with even if their latest ad changes later; .7 saving ad 111 into a second group on the same page → refused with the other group's name; the same ad in a group on another page is allowed; .8 "Ads not in a group yet" shows ads seen for the page with names, customers and last time; ticking two and "Add to group" adds them; typing "111, 222\n333" parses three IDs and rejects non-digits; .9 group edits create history rows and Restore brings back an old value; deleting a group → its ads fall back to page values; .10 a user who cannot edit page values cannot see or post to Ad groups (403, nothing written); .11 the Forbeast page values API, chatblast and the setup check still read only the page defaults; .12 existing Chatbot / Chatblast / Botcake / PageSettings suites pass. P2: .13 390 px; .14 test run with a chosen group on /chatbot.
