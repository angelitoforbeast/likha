# Brief 178: Ads Manager data is complete every day, and bad data is refused and reported

## Why
The Ads Manager report (ads_manager_reports) is filled by staff uploads and, once write mode is on, by the Meta sync for the selected ad accounts (spec 173). The owner wants to be sure the data is always there and right: a new ad account must not be missed (it may need manual uploads until someone with access connects it), every account must be updated daily by the sync or by staff, and a fetch or upload that lowers a value already stored for a day (spend, impressions, reach…) is wrong data and must be refused and reported, not silently accepted.

## Decisions (do not reopen)
| # | Decision | Why |
|---|---|---|
| 1 | **Account coverage list** on /ads_manager/report (Meta section or a "Data health" box): every ad account known from (a) the Meta connections, (b) /ads_manager/ad_account active rows, (c) uploads (map uploaded ad_id/campaign_id to accounts via ad_campaign_creatives.account_id or the latest Compare/API data — use what exists; an uploaded ad whose account cannot be told is grouped as "account unknown"). Per account: name (176 rules), source of its data (API selected / upload only / none), latest day with data, rows and spend for yesterday, and a status: **OK** (yesterday has data), **Missing yesterday** (it had spend in any of the 3 days before but nothing yesterday), **New** (first seen in the last 3 days, from any source), **Not readable by API** (in uploads or ad_account but in no connection — needs a manual upload or someone with access to connect). Visible to the roles that see the Ads page. | Owner: be sure no account is missed and each is updated daily. |
| 2 | **Daily check**: a scheduled command at 12:00 Manila (config) evaluates decision 1 for yesterday and records the result (app_settings JSON or upload_logs type, no new table). If any account is Missing yesterday / New / Not readable, show a red notice at the top of /ads_manager/report and on the Chatbot/Chatblast banner area is NOT needed — only the Ads pages. Also expose the result to a read-only artisan command `ads:data-health --json` for monitoring. | Daily assurance. |
| 3 | **Refuse lower values.** For an existing (day, ad_id) row, any incoming value (from the sync or an upload) lower than the stored one for spend, impressions, reach, results, link_clicks, messaging_conversations_started, purchases is **refused for that row** (the row keeps all stored values — check what the existing monotonic protection does per column and make it all-or-nothing per row, so a row is never half-updated with mixed old/new numbers) and **recorded**: source (sync run id / upload id + user), day, ad_id, account, which metric, stored vs incoming. Show per run/upload "N rows refused (lower values)" with a details list, and a daily total in the data health box. Equal or higher values update as today. Rows for days older than 7 days may still update upward. | Owner: a drop means wrong data; reject and report. |
| 4 | **New ad accounts in the sync** stay ticked by default (173-1); the coverage list marks them New for 3 days. Accounts unticked by a person are listed as "Not synced (unticked)" so it's visible. | Nothing silently ignored. |
| 5 | No change to Compare math, page name/delivery/result mapping (173), the schedule times, the upload file format, or write-mode rules. No new tables. | Safe. |

## Cases (S-178)
P1: .1 coverage list shows an API-selected account OK, an upload-only account OK, an account with spend 2 days ago and nothing yesterday as Missing yesterday, a first-seen-today account as New, an ad_account row in no connection as Not readable, an unticked one as Not synced; .2 the 12:00 command records the result and the red notice shows when any account is not OK; `ads:data-health --json` prints it; .3 a sync row with impressions lower than stored → the whole row is kept, a refusal recorded with both numbers, the run shows "1 row refused"; same for an upload; equal/higher → updated; .4 non-Ads roles cannot see the box (same access as the Ads page); .5 existing MetaAds, AdAccount and Ads Manager upload tests pass.
