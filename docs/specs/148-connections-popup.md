# Brief 148: /chatbot/pages — one Connections popup per page, a Connected column, a safe Flow picker and Sheets-style header filters

## Why
On /chatbot/pages (`resources/views/chatbot/index.blade.php`, data from `ChatbotController`) the owner cannot tell which pages are connected to Botcake or Forbeast. The Forbeast token is added per page through a browser `prompt()` with Add token / New token / Test / Clear buttons squeezed into the Active cell (`forbeastBox`, around line 525), and again in page settings (`resources/views/page_settings/index.blade.php`, the `forbeast.token` lines). The Botcake "Chat to site" block (`app/Services/BotcakeChatBlock.php::turnOn`) is a separate step, so pages with a valid token got no chats (Incepxion Daily Selection, 2026-10-24). The Flow dropdown in each row is easy to change by accident.

## Decisions (do not reopen)
| # | Decision | Owner's reason |
|---|---|---|
| 1 | **Connections popup per page** (a modal, opened by a "Connections" button next to Edit and Preview in the Page cell). Two cards with the same layout: **Botcake** (Page ID, Token) and **Forbeast** (Page ID, Token). The Forbeast Page ID is prefilled from the Botcake page ID (same Facebook page id) and editable. Token fields are masked (last 4 shown), never echoed back in full. | "may hiwalay na popup for gantong setting"; "same lahat, need lang iconnect yung token and page id". |
| 2 | **Saving a pasted token tests it at once** (no separate Test click): Botcake through the existing Botcake token test, Forbeast through `ForbeastPageSetup::connect`. The card shows the page name the provider returns; if it does not match this Likha page (case- and space-insensitive name compare, or the provider's page id differs from the entered Page ID), show it red and **do not save** the token. Saves go through `PageSettings` (history rows with the user id, as today). | "pagkalagay ng token, rekta test na". |
| 3 | **Botcake: a passing token turns the chat block on automatically** (`BotcakeChatBlock::turnOn`, keeping the existing chat.key, no rotate). The Botcake card also has a "Fix chat block" button that re-applies it any time (idempotent, same key). One line in the popup says it replaces the page's Default Reply in Botcake. | "eto dapat"; re-applying is fine. |
| 4 | **Takeover guard**: before connecting, if the provider shows the page already points to another site (Botcake Default Reply JSON API block whose URL host differs from this app's host, e.g. incepxion.pro; Forbeast page webhook URL differs from this app's /api/gateway/events, if the Forbeast API returns it), ask to confirm ("Connected to incepxion.pro now. Move it to this site?"). If the Forbeast API does not expose the current webhook, record that in Open points and skip that half. | Likha and Incepxion share the same Forbeast and Botcake accounts. |
| 5 | **Remove** the row's Forbeast Add/New token/Test/Clear buttons and the browser prompt; in page settings replace the Forbeast token lines with a link to /chatbot/pages (for the Botcake ID/token lines in page settings pick the smallest change: keep, make read-only, or link; say which in the result). | One place for setup. |
| 6 | **Bot** (the existing provider select): list only bots that are connected (complete). One connected bot: plain text, no select. Changing it asks to confirm ("Switch Tech Flask Ph from Botcake to Forbeast?"). | "makikita lang dito yung actual bot na magagamit sa dropdown". |
| 7 | **Connected column**: plain text of the complete connections: "Botcake", "Forbeast", "Botcake, Forbeast", or "—". Complete means Botcake: page id + token OK + chat block on (chat.key present); Forbeast: `ForbeastPageSetup::info()['connected']`. An incomplete connection is not listed; its reason goes into the **Check** column next to the other X lines (e.g. "Botcake: no chat block", "Forbeast: token not working"), using the existing setup check (`PageContentCheck::setup`). | "text lang dapat, kung anong bot nakaconnect". |
| 8 | **Flow**: the cell shows the flow name as text with a small ✎; ✎ opens a popup with a searchable list of flows (and "No flow"); saving asks to confirm "Change flow: Main Flow → Encode Order?" and writes through the existing link path so the Changes log (spec 146) records who and when. | The dropdown is too easy to change by accident. |
| 9 | **Header filters, Google-Sheets style** on the table's columns (at least Page, Active, Bot, Connected, Flow, and Check status ok/x/warn): a panel under the header with a search box, the actions **"Check all · Uncheck all"** (actions, not a checkbox), and one checkbox per value. Connected's values: Botcake, Forbeast, None (a page with both matches both). Filters combine with AND across columns. Header row sticky, only rows scroll; no horizontal page scroll; usable at 390 px. | Owner's standing table rule; "uncheck all, at check all para tamang term". |
| 10 | **Nightly re-test** (scheduled in routes/console.php, after the existing botcake:setup-check, as one command): every page's Botcake token and chat block (re-apply the chat block when it is missing on a page whose bot is active and whose provider is Botcake) and Forbeast token; results into the existing *_status settings so the Connected and Check columns reflect them. Logs counts only, no tokens. | Catch expired tokens and removed chat blocks. |

## Threat model
Trusted: logged-in users with the page-edit permission (the same access rule as today's token routes; reuse it). Untrusted: provider responses (names, URLs); escape everything shown. Tokens are secrets: stored as today (is_secret), never returned in JSON beyond the last 4, never logged.

## Cases (add as S-148 to qa/stories.md, as a table like S-145: ID, P, Given/When/Then, Test, Status)
