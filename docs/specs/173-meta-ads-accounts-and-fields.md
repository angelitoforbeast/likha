# Brief 173: Meta Ads sync — choose the ad accounts, and make page name, delivery and result type match the upload

## Why
Spec 154 (docs/specs/154-meta-ads-connect.md and .result.md) lets staff connect Facebook on /ads_manager/report; Compare (app/Services/MetaAds/Compare.php) and Sync (Sync.php, Insights.php) read every ad account of every connection. Three people are connected (about 9 distinct accounts). The first live Compare (Oct 20–26) matched the uploads within ₱66 of ₱728,219, and all upload spend sits in 5 accounts; the other 4 have no spend. A full column check of 34 ads against the upload (Oct 26) found three gaps that block turning write mode on:
1. **page_name is empty for every API row.** Cause, confirmed live: (a) for ads that use an existing post the creative has no `object_story_spec.page_id`; the page ID is in `creative.actor_id` or the prefix of `creative.effective_object_story_id` ("<pageid>_<postid>"); (b) reading a Page's `name` fails with Graph error 100 "requires the 'pages_read_engagement' permission", which the app does not have. Sync::withPageNames then falls back to an earlier upload row of the same ad, so a brand-new ad is skipped (page_name is NOT NULL). Likha already stores each Facebook page ID: page_settings provider `botcake`, key `page_id` (66 pages), e.g. 602349066290691 = "Joy Villaluna", 970868019448492 = "Sienna Lopez" — the same names the upload has.
2. **Delivery wording differs** from the export.
3. **Result type wording differs** from the export.

## Evidence (data, from production, 2026-10-28; Oct 26 rows of 3 accounts, API status vs the uploaded export)
Delivery pairs (count, campaign effective_status => upload campaign_delivery | ad set effective_status => upload ad_set_delivery):
- 158: PAUSED => not_delivering | CAMPAIGN_PAUSED => not_delivering
- 43: ACTIVE => active | ACTIVE => active
- 3: PAUSED => active | CAMPAIGN_PAUSED => active (paused after the export was taken; ignore)
- 2: PAUSED => not_delivering | PAUSED => inactive
- 2: ACTIVE => not_delivering | PAUSED => inactive
Result type pairs (campaign objective / ad set optimization_goal => upload result_type):
- 206: OUTCOME_SALES / MESSAGING_PURCHASE_CONVERSION => "Meta purchases"
- 2: OUTCOME_ENGAGEMENT / MESSAGING_PURCHASE_CONVERSION => "Meta purchases"
Upload values in the last 30 days: campaign_delivery not_delivering 17,762 / active 3,314 / inactive 90; ad_set_delivery not_delivering 17,519 / active 3,314 / inactive 333; result_type "Meta purchases" 19,981 / "Messaging conversations started" 1,123 / "Meta purchase conversion value" 62.

## Decisions (do not reopen)
| # | Decision | Why |
|---|---|---|
| 1 | **Choose accounts.** On /ads_manager/report's Meta section, list every ad account from all connections once (account name, ID, which person's connection reads it), each with a checkbox, and the account's numbers from the **latest Compare** if one exists (upload rows, API rows, upload spend, API spend; "not in uploads" when upload spend is 0). Save stores the selection as one `app_settings` row (e.g. `meta_ads.accounts`, JSON list of IDs) — no new table. **Sync (button and schedule) reads only selected accounts**; with no selection saved, Sync does nothing and says "Choose the ad accounts first". **Compare** reads the selected accounts, or all accounts while nothing is selected (so it can help choose). A new account that appears later is unticked. Saving the selection is **CEO only** (same as write mode); others see it read-only. Log each change (who, when, before/after) like the other Meta Ads events. Add `php artisan meta-ads:accounts {--list} {--set=ID,ID,...}` for operations (same validation: only IDs that appear in a connection; prints counts, never tokens). | Owner: selectable data, chosen from what the staff upload. |
| 2 | **Page name without new Meta permissions.** Page ID = `creative.object_story_spec.page_id`, else `creative.actor_id`, else the part before "_" of `creative.effective_object_story_id` (request those fields). Name = the Likha page whose active page_settings row (provider botcake, key page_id — check for other providers that store a Facebook page ID and include them) has that ID. If none: the page_name of an earlier upload row for the same ad (existing fallback). If still none: skip the row as today, but record the skipped ad IDs and page IDs on the run log so they can be fixed. Remove the Page `?ids=…&fields=name` call (it always fails). | Confirmed cause; Likha already knows its pages. |
| 3 | **Delivery wording = the export's.** ad_set_delivery: ACTIVE → `active`; PAUSED → `inactive`; CAMPAIGN_PAUSED → `not_delivering`. campaign_delivery: `active` when the campaign and this ad's ad set are both ACTIVE; otherwise `not_delivering` (covers PAUSED campaigns and an ACTIVE campaign whose ad set is PAUSED). Other effective_status values (ARCHIVED, DELETED, WITH_ISSUES, IN_PROCESS, PENDING_REVIEW, DISAPPROVED, ADSET_PAUSED for ads…) → `not_delivering`. Keep the mapping in one place (a constant or config array) with a comment on the evidence; the export's rare campaign `inactive` (90 rows / 30 days) is not produced — note it in the result. | Match the upload so reports and filters behave the same. |
| 4 | **Result type wording = the export's.** optimization_goal MESSAGING_PURCHASE_CONVERSION, OFFSITE_CONVERSIONS and other purchase goals → "Meta purchases"; CONVERSATIONS → "Messaging conversations started"; VALUE → "Meta purchase conversion value"; keep the existing mapping for the rest. One table in Insights::RESULT_TYPES, with the evidence in a comment. | Same reason. |
| 5 | No change to the upload, the Compare math, write-mode rules, the schedule, ads_manager_reports columns, or Forbeast. No new tables. | Small and safe. |

## Cases (S-173)
P1: .1 the Meta section lists each account once with its latest Compare numbers and a checkbox; a CEO saves 2 of 5 → the selection row holds exactly those IDs and an event is logged; a non-CEO sees the list read-only and the save is refused (403); .2 Sync with no selection → no Graph calls, message "Choose the ad accounts first"; Sync with a selection → Graph calls only for selected accounts (Http faked); Compare with no selection → all accounts; with a selection → only those; .3 `meta-ads:accounts --set=` refuses an ID that is not in any connection and sets valid ones; `--list` prints IDs, names, selected yes/no, no token; .4 page name: an ad whose creative has only actor_id 602349066290691 → page_name "Joy Villaluna" from page settings; only effective_object_story_id "970868019448492_1221…" → "Sienna Lopez"; an unknown page ID with an earlier upload row → that row's name; unknown and no earlier row → skipped and listed on the run log; no request for the Page's name is made; .5 delivery: each evidence pair above maps to the export value (except the 3 stale ones); .6 result type: MESSAGING_PURCHASE_CONVERSION → "Meta purchases", CONVERSATIONS → "Messaging conversations started", VALUE → "Meta purchase conversion value"; .7 existing 154 tests and the Ads Manager upload tests pass. P2: .8 390 px.
