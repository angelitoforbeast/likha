# Brief 133: shadow-encode every page's orders from the Likha import and compare with the final order

## Why
Spec 130's shadow only sees pages whose orders pass through the Likha bot's Sheet step (two pages). The owner wants to know, for **all** pages, whether Likha encodes and decides PROCEED correctly, judged against the **final order** in `macro_output` (what the sheets + staff produced). Every page's orders already reach Likha through the Likha import (`ImportLikhaFromGoogleSheet`, tab "TO WEBSITE" A2:I — a formula copy of "All Orders": A date text "HH:mm dd-MM-yyyy", B page, C FB name, D phone, E all user input, F shop details, G extracted details, H price, I DONE marker), which is the same input the AUTO ENCODE script reads.

A one-off backtest (2026-10-23) rebuilt inputs from `macro_output` fields for 1,485 orders of 40 pages: location equal to the final order 93.6% for orders that went PROCEED untouched, Likha would PROCEED 92.1% of those, 101 orders had blank shop details because the rebuilt input was incomplete. The real TO WEBSITE cells remove that guesswork.

## Decisions (do not reopen unless something is actually broken)
| Decision | Why |
|---|---|
| **Hook in the Likha import:** when the import **creates** a new `macro_output` row (not on updates), and the global switch is on, create an `order_encodes` row from the **raw TO WEBSITE cells of that row** (A–H exactly as read, before the import's own transformations) and dispatch `EncodeOrder`. Key: `spreadsheet_id` = the order spreadsheet id, `tab` = "All Orders", `row_number` = the sheet row number (TO WEBSITE row = All Orders row), so a Bianca/Joy order already encoded by the flow's shadow hook is **not** encoded twice (firstOrCreate on that key; if the row exists, only set its `macro_output_id`). Set `macro_output_id` on the new row. Mark the source in `input` (`source: import`). The import never waits for the encode and never fails because of it (catch, report, continue). | Exact input for every page, no doubles. |
| **Switch and cap in `app_settings`:** `order_encode_import_shadow` = `off` (default) / `on`; `order_encode_import_daily_cap` (default 2000) — past the cap that day, skip and count the skipped orders (shown on the page). Pages listed in `order_encode_import_skip_pages` (comma list, default empty) are skipped. Editable on the `/order-encode` page by the same people who can open it (CEO), with history like other app settings if the project has it. | Cost control: measured ≈ $0.003 per order (gpt-5.2 checker calls are most of it), ≈ $4–5 per 1,500 orders. |
| **Compare with the final order:** command `order-encode:compare-final` (every 15 min) takes import-shadow rows (and flow-shadow rows that have `macro_output_id`) that are done and not yet final-compared, waits until the `macro_output` row has been filled by the Macro import (STATUS or APP SCRIPT CHECKER or PROVINCE not blank) or 72 h passed ("sheet never finished"), and compares field by field: province, city, barangay (Ñ = N, case-insensitive, trimmed), address line (normalised text: lowercase, punctuation and repeated spaces folded), item, COD, **PROCEED** (Likha's final O = ✅ vs `STATUS` = PROCEED), and Likha's final O vs `APP SCRIPT CHECKER`. Also record whether staff **edited** the order (`edited_*` flags) and its STATUS at compare time. Store the result in the existing columns if possible (e.g. a `final` key inside `compare` and a separate state key); add one nullable JSON column only if there is no clean way — then it is the only migration, additive. | The final order is the truth the owner cares about. |
| **Page `/order-encode`:** a tab **"All pages (vs final order)"** next to the current sheet compare: date range + page filter; tiles: orders, % location equal, % address equal, % item/COD equal, and a **PROCEED table**: rows = final (PROCEED untouched / PROCEED after staff edit / not PROCEED), columns = Likha would PROCEED / would hold, counts and %. Per-page table (orders, location %, PROCEED agreement %), sortable. A list of disagreements with both values side by side and the steps log on hover (reuse spec 130's components). Show the switch, cap, skip list, today's encoded/skipped counts and estimated cost (from `usage` and the existing price map). Read-only except the three settings. English UI. | The owner reads readiness per page from one screen. |
| Queue `encode` as today (2 workers per server); note in the result whether more are needed for the import bursts (an import can create hundreds of rows at once) and the expected backlog time. | Deploy knows what to change. |
| Incepxion runs the same code; the switch stays off there until the owner says. | Same line, separate decision. |

## Threat model and risk
Untrusted: sheet cells and customer text (escape on the page; GPT output validated by spec 130's rules). Trusted: CEO settings. Risk tier: medium — runs inside the order import; it must never change what the import writes to `macro_output` or slow it noticeably (dispatch only, no GPT in the import job).

## Done when
- Tests: switch off → import behaves exactly as before and creates no `order_encodes`; switch on → one encode per created order with the raw A–H cells and the right row key, none on update, none for a row already encoded by the flow hook (only `macro_output_id` set), cap and skip list respected and counted; an encode failure never fails the import; compare-final waits for the Macro import, then marks equal/different per field including PROCEED and edited flags, and "sheet never finished" after 72 h; the page shows the tiles, PROCEED table, per-page table and disagreements, escapes text, and saves the three settings for the CEO only.
- `php vendor\phpunit\phpunit\phpunit tests/Feature/OrderEncode tests/Feature/Chatblast tests/Feature/PageSettings tests/Feature/Botcake tests/Feature/NightRun` plus your new tests pass (the import tests in particular); note the known local-only failure (missing Google credentials file) separately.
- Result: files, settings keys, the compare storage you chose (migration or not), the import hook point, expected cost and backlog, commits.

## Out of scope
Turning the switch on; the Macro import; changing encode rules or models; deploy.
