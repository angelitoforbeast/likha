| A1 | The 30 days are enforced by the server, with your option c: at a CEO password login the server also issues a second cookie, encrypted by the framework like its other cookies, that holds the time of that login (and the user id it was issued for). A sign-in that comes from the remember cookie is accepted only when this second cookie is present, decrypts, belongs to the same user id, and is not older than 30 days; otherwise the remembered sign-in is refused exactly as a non-CEO one is (logged out, both cookies cleared, token cycled). The second cookie has the same lifetime and the same Secure, HttpOnly and SameSite treatment as the remember cookie, and Logout clears it. No migration. | Mira's decision: the owner asked for 30 days ("30 days login na di maglologout"); a copied cookie that works for longer than that is not what he approved, and the check must not depend on the browser honouring an expiry. Option c because it needs no schema change and stays in the two files this handoff already touches. |
| A2 | A password change ends remembered logins: wherever this app changes a user's password (the owner's user page and any self-service change you find), the remember token of that user is cycled in the same request, so every remember cookie issued before the change stops working. If the app changes passwords in more than two places, list them and stop before editing a third. | Mira's decision: changing the password is what the owner will do if he thinks a device was lost; with a 30-day login it has to cut that device off. Your RESULT.md says it does not today. |
| A3 | Deploy safety for the listener: the role re-check must not depend on a cached events file being rebuilt. Register the listener explicitly (in the app's service provider or the place this app registers listeners) in addition to or instead of discovery, so that a stale events cache cannot silently switch the re-check off; and keep the deploy note that says how to verify it on the server. | Mira's decision: a security check that can be off without any error is not acceptable. |
